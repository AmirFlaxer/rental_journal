# פרוטוקול סגירת סשן - rental_journal

**הכלל המרכזי:** לאמת **בפקודה**, לא מהזיכרון. שלוש פעמים נשאל אמיר "הכל בזיכרון?", בשלושתן
התשובה האינטואיטיבית הייתה "כן", ובשלושתן היו פערים אמיתיים - בפעם השלישית (27/7/2026) גם
כשהשאלה נשאלה **דקות אחרי** שהוכרז "הכל נסגר". תחושת-שלמות אינה ראיה.

## מה מיוחד בפרויקט הזה

חמישה דברים שמפילים סגירת-סשן כאן דווקא, וכולם נצפו בפועל:

1. **מצב-הפרויקט **אינו** ב-`~/.claude/current_focus.md`.** הוא הועבר לריפו בכוונה
   (קומיט `eeb1bba`), כי הקובץ הגלובלי חוצה-פרויקטים. מקום-השמירה הפרויקטלי הוא
   **`docs/current_focus.md`** שבריפו. אל תכתוב מצב rental_journal לקובץ הגלובלי.
2. **ל-CI יש שני jobs: `checks` ו-`deploy`.** `gh run list` מראה `success` ברמת-הריצה,
   אבל דחיפה ל-main **פורסת לייצור** - ולכן צריך לאמת ששניהם עברו, לא רק שהריצה ירוקה.
3. **`npm run build` הוא הגייט היחיד שתופס בעיות גבול-client.** `tsc`/`lint`/`vitest`
   עוברים גם כשעמוד ב-`dashboard` שמרנדר `Icon` חסר `"use client"`.
4. **מיגרציות נדחפות ידנית לפרודקשן**, ולכן `supabase/migrations/README.md` הוא מקום-שמירה
   בזכות עצמו: טבלת-הסטטוס שלו חייבת לשקף מה באמת רץ. אם שינית סכימה - גם
   `npm run gen:types`, אחרת הטיפוסים הנוצרים סוטים ואף שער ב-CI לא יכול לתפוס עמודה חסרה (נצפה: `check_bounces`
   נעדר מהם לגמרי במשך שבוע).
5. **`package-lock.json` נכנס ל-dirty מעצם הרצת npm ב-Windows** (`@next/swc-win32-x64-msvc`).
   זה לא שינוי-תלויות ואין לקמט אותו - `git checkout -- package-lock.json`.

## שלב 1 - לשמר את העבודה

1. **גיט:** commit + push לכל שינוי שטרם נדחף.
2. **מסמכי-האמת בריפו:** `SPEC.md` (מצב והחלטות) · `TODO.md` (משימות פתוחות) ·
   `docs/session-log.md` (בלוק-סשן חדש) · `docs/current_focus.md` (נקודת-הכניסה לסשן הבא).
3. **זיכרון:** `~/.claude/projects/c--Projects-rental-journal/memory/` - קובץ הנושא + שורה
   ב-`MEMORY.md`.

## שלב 2 - סריקת מקומות-השמירה (חובה, כל אחד בפקודה)

- [ ] **`docs/current_focus.md`** - האם הוא מתאר את המצב **הנוכחי**? זה מה שסשן הבא קורא
  ראשון. לבדוק **תוכן** ולא תאריך: `grep -c "<מילת-מפתח מהסשן>" docs/current_focus.md`.
  ⚠️ פריט "הבא בתור" שכבר נבנה ישלח סשן עתידי לעבוד על מה שהושלם.

- [ ] **`SPEC.md` §הצעד הבא** - האם פריט שנסגר בסשן עדיין רשום כפתוח? זה הפער שנצפה בפועל:
  הסעיף הכריז "אין TODO טכני-דחוף פתוח" בזמן שענף שלם חיכה לא-מוזג.

- [ ] **`TODO.md`** - פריט שבוצע נשאר ברשימה? פריט חדש שעלה בסשן ואינו רשום?

- [ ] **`memory/MEMORY.md`** - האם התיאורים עדיין **נכונים**? זה מה שנטען בתחילת כל סשן.
  **תיאור מיושן גרוע מהיעדר תיאור.**

- [ ] **`~/.claude/LESSONS.md`** - האם עלה לקח **חוצה-פרויקטים**? לא כל לקח פרויקטלי שייך
  לשם, אבל לקח שיחזור בפרויקט אחר - כן. לציין בסוף לאילו הקשרים רלוונטי.

- [ ] **גיט - שלוש בדיקות נפרדות:**
  ```bash
  git status --short                                    # נקי?
  BR=$(git branch --show-current)                       # לא לקבע main - בענף-פיצ'ר זה פער-שווא
  git rev-list --left-right --count origin/$BR...$BR    # 0 0 ?
  gh run view --json jobs -q '.jobs[] | "\(.name): \(.conclusion)"'   # checks וגם deploy
  ```
  **"נקי מקומית" אינו "נדחף"**, ו**"נדחף" אינו "עבר CI"**, ו**"CI ירוק" אינו "נפרס"** -
  צריך את כולן.

- [ ] **סביבה:** שרת dev/prod מקומי נסגר? `netstat -ano | grep ":3000 .*LISTENING"`
  (Windows מרשה שני תהליכים על אותו פורט - אחד מגיש HTML חדש והשני CSS ישן).
  צילומי-מסך וקובצי-scratch שנוצרו בשורש הריפו - נמחקו?

## שלב 3 - סריקה-הפוכה (חובה לפני אמירת "הכל בזיכרון")

שלב 2 בודק ממקום-השמירה אל הסשן. זה מפספס את הפער ההפוך: דבר שנעשה בסשן ואין לו **שום** בית.

1. **להוציא את מה שנעשה בפועל, בפקודה:**
   ```bash
   git log --oneline -20
   git diff --stat HEAD~5..HEAD
   ls -lt ~/.claude/projects/c--Projects-rental-journal/memory/ | head
   ```

2. **לעבור פריט-פריט** ולשאול לכל אחד: איפה הוא חי אחרי שהסשן ייסגר?
   - החלטה או כיוון שנבחר: `memory/project_*.md` או `SPEC.md`
   - הנחיה של אמיר על **איך לעבוד**: `memory/feedback_*.md`
   - לקח שיחזור בפרויקט אחר: `~/.claude/LESSONS.md`
   - עבודה שנקטעה והצעד-הבא: `docs/current_focus.md`
   - שינוי סכימה שהורץ בפרודקשן: `supabase/migrations/README.md`

3. **ארבעה פערים שחוזרים כאן** ושווה לחפש במפורש:
   - **דרך-ללא-מוצא:** ניסיון שנכשל ובוטל. אם לא נרשם, סשן עתידי ינסה אותו שוב.
   - **"למה לא" מתועד:** אפשרות שנפסלה. הנימוק שווה יותר מהמסקנה.
   - **ידע-מחוץ-לריפו:** מיגרציה שממתינה, מצב ההתקנה של ה-PWA במכשיר, שלב-אימות ידני.
   - **בדיקה שהפכה כיוון:** בדיקה קיימת ששונתה בגלל הכרעת-מוצר. זה מותר, אבל חייב להיות
     מתועד בהערה מעליה **ובהודעת הקומיט** - אחרת זו נראית כריכוך-בדיקה.

## שלב 4 - בדיקת-אמת: האם מה שכבר כתוב במסמכים עדיין **נכון**? (חובה)

שלבים 2-3 בודקים שני כיוונים - ממקום-השמירה אל הסשן, ומהסשן אל מקום-השמירה -
**ושניהם מניחים שמה שכבר רשום במסמך נכון.** זו ההנחה שנשברה: השלב הזה נוסף ב-27/7/2026 אחרי שהשאלה
"הכל בזיכרון?" נשאלה **דקות אחרי** שהוכרז "הכל נסגר", והסריקה מצאה **שני פריטים ב-TODO
שתיארו מציאות מלפני חודשיים**. פריט-פתוח מיושן אינו רעש: הוא שולח סשן עתידי לעבוד על מה
שכבר גמור, וזה בזבוז שקט שאף בדיקה אחרת לא תופסת.

**השיטה: לכל פריט שרשום כפתוח, לאמת את הטענה שלו בפקודה - לא לקרוא אותה ולהאמין.**
הפריט מצביע על משהו קונקרטי, ולכן הוא בדיק:

| מה הפריט טוען | איך מאמתים |
|---|---|
| "קבצים לא-מקומיטים" | `git ls-files <הקבצים>` - אם הם חוזרים, הם מקומטים |
| "השורה הזו עושה X" | `grep -n "<הקוד>" <קובץ>` - האם היא עוד שם, ובאותה שורה |
| "ברירת-המחדל היא Y" | לגרפ את הערך בקובץ שהפריט מצטט |
| "צריך לרשום ל-gitignore" | `git ls-files <קובץ>` + `git check-ignore -v` |
| "מיגרציה טרם הורצה" | טבלת-הסטטוס ב-`supabase/migrations/README.md`, ואם יש ספק - לשאול את אמיר |
| "הענף לא מוזג" | `git branch --merged origin/main` , או חיפוש הקומיט ב-`git log origin/main` |

**מה עושים עם התוצאה:**
- פריט שהתברר כגמור - **לסמן כנסגר עם המילים "אומת בפקודה" והתאריך**, ולא למחוק. מי שיקרא
  אחר-כך צריך לדעת שזו בדיקה ולא הנחה.
- פריט שהתברר כפתוח באמת - **לומר זאת במפורש בדיווח.** "בדקתי ועדיין פתוח" הוא מידע, ובלעדיו
  אין דרך לדעת אם הפריט נבדק או רק לא נגעו בו.
- לעדכן את חותמת-התאריך בראש `TODO.md`, כולל אילו פריטים נבדקו.

**איפה לחפש במיוחד:** פריטים שנכתבו לפני חודש ומעלה · פריטים שמתארים "עבודה בתהליך" (הן
מתיישנות ראשונות) · פריטים שנכתבו בסשן אחר מזה שסוגר עכשיו.

⚠️ **התשובה ל"הכל בזיכרון?" לעולם אינה מבוססת על בדיקה שרצה מוקדם יותר באותו סשן.** הסשן
המשיך מאז, ובדיוק כך נולד השלב הזה.

## שלב 5 - לדווח

לסכם מה נבדק ומה נמצא. **אם נמצא פער - לומר אותו במפורש**, לא לתקן בשקט ולדווח "הכל תקין".
לא לומר "הכל בזיכרון" אלא לומר מה נבדק: "4 קומיטים נדחפו, CI ירוק בשני ה-jobs, שני
קובצי-זיכרון עודכנו, שני פריטי-TODO אומתו בפקודה ונסגרו כמיושנים, ואחד אומת כפתוח באמת".
אם הסריקה לא העלתה כלום - לומר זאת כתוצאה של סריקה שרצה, ולא כתחושה.

## אם נשאל "הכל בזיכרון?" באמצע סשן

**להריץ את שלבים 2, 3 ו-4 גם אז, מחדש.** זו בדיוק השאלה שחשפה את הפערים בכל שלוש הפעמים
שנשאלה - כולל פעם אחת שבה היא נשאלה **דקות אחרי** שהוכרז "הכל נסגר", ומצאה שני מסמכים
מיושנים. בדיקה שרצה מוקדם יותר באותו סשן אינה תשובה: הסשן המשיך מאז.

**התשובה הנכונה אינה "כן" אלא מה נבדק ומה נמצא.** אם נמצאו פערים - לומר אותם, ולומר גם
שהשאלה היא שחשפה אותם.
