# אפיון: ביטוח שנתי, אחריות לפי אכלוס ואופק מתגלגל

> נוצר 2026-07-26 בעקבות brainstorming עם אמיר.

## הבעיה

שלוש בעיות נפרדות באותו מנגנון - תזכורות חשבונות השירות של נכס.

**1. אין ביטוח.** `UtilityType` תומך במים, גז, חשמל, ארנונה, ועד בית ואחר. `UtilityFrequency` תומך בחודשי ודו-חודשי בלבד. ביטוח מבנה מתחדש **פעם בשנה, ללא קשר לשוכר** - ואין לו מקום במודל.

**2. האחריות לא עוברת אליך כשהנכס ריק.** `responsibility` היא הגדרה סטטית לכל חשבון, ו-`generateVirtualUtilityTasks` **מדלג לגמרי** על חשבונות `tenant_pays`. כשאין שוכר, כל התשלומים חלים על הבעלים - וזה בדיוק המצב שבו התזכורת הכי נחוצה, ובו היא לא מופיעה.

**3. אין ראייה קדימה.** המחולל מייצר לחודש הנוכחי בלבד, ולכן לנכס ריק אין תמונה של החשבונות שיחולו עליך עד סוף השנה.

**רקע:** ב-DB יש 72 תזכורות ישנות שנוצרו ב-30.3.2026 ממחולל שכבר לא קיים בקוד, שפרס תזכורות **עד שנת 2049** - תזכורת ביטוח שנתית עד 31.10.2049 וחשבונות דו-חודשיים עד 2030. הן הוסתרו מהמסך בעבודה קודמת אך לא נמחקו, כי תזכורת הביטוח השנתית היא הדבר היחיד מביניהן ששווה שימור ואין לו תחליף במודל הנוכחי.

## המטרה

מודל תזכורות שמכיר בביטוח, מעביר את האחריות אליך כשהנכס ריק, ומגביל את עצמו לאופק של שנה - כך שמחיקת 72 השורות הישנות תהפוך ממחיקת פיצ'ר למיגרציה.

## החלטות מ-brainstorming

<div dir="rtl" align="right">

| שאלה | הכרעה |
|---|---|
| איפה ביטוח יושב | הרחבה של `property_utilities` - היא כבר ברמת הנכס ולא ברמת החוזה, בדיוק מה שביטוח דורש |
| נכס ריק - מה עם `tenant_pays` | **הכל חל על הבעלים**, כולל חשבונות שהוגדרו כמשולמים ישירות בידי השוכר |
| למה צריך תזכורות קדימה | **שניהם** - גם תזכורת בחודש שלה, וגם תמונה מקדימה של החשבונות שיחולו עליך |
| סכומים כספיים בתחזית | **לא בשלב זה.** רשימת חשבונות לפי חודש, בלי סכום |
| אופק | מסיום החוזה ועד `min(סוף השנה הקלנדרית, תחילת החוזה הבא)`, מתגלגל בכל 1 בינואר |

</div>

**החלטת הסכומים מקצצת את המימוש משמעותית** - לא נדרשת עמודת סכום, לא נדרש חישוב ממוצע מהיסטוריית ההוצאות, ולא נדרש כרטיס סיכום כספי.

## שינויים במודל הנתונים

<div dir="rtl" align="right">

| שינוי | פירוט |
|---|---|
| `UtilityType` | מתווסף `insurance` |
| `UtilityFrequency` | מתווסף `annual` |
| `property_utilities.anchor_day` | עמודה חדשה, `int` nullable. לתדירות שנתית נדרש יום **וחודש** (31.10), לא רק חודש |

</div>

מיגרציה: `alter table property_utilities add column if not exists anchor_day int;`

`anchor_day` רלוונטי ל-`annual` בלבד. בתדירות חודשית ודו-חודשית התזכורת נשארת מעוגנת ל-1 בחודש כמו היום.

## כללי הייצור

### אחריות אפקטיבית

```
אחריות אפקטיבית(חשבון, מאוכלס) =
    חשבון.type === "insurance"  ->  owner_pays   (תמיד, ללא קשר לאכלוס)
    מאוכלס                       ->  חשבון.responsibility
    ריק                          ->  owner_pays
```

השורה השלישית היא השינוי המהותי: בנכס ריק גם חשבון `tenant_pays` מייצר תזכורת, במקום להידלג.

| `owner_forwards` | `העברת חשבון {תווית} לשוכר - {נכס}` |
| `owner_pays` | `תשלום {תווית} - {נכס}` |

### חלון הייצור

<div dir="rtl" align="right">

| מצב הנכס | חודשים שנוצרים |
|---|---|
| מאוכלס (יש חוזה פעיל) | החודש הנוכחי בלבד - ללא שינוי מהיום |
| ריק | מתחילת הריקות ועד האופק |

</div>

```
אופק = min( 31 בדצמבר של השנה הנוכחית,
            היום שלפני תחילת החוזה הבא אם קיים )

תחילת הריקות = max( תאריך סיום החוזה האחרון, תחילת החודש הנוכחי )
```

בכל 1 בינואר האופק מתגלגל אוטומטית לסוף השנה החדשה, ולכן אורך התחזית לעולם אינו עולה על שנה. זה מה שמונע את חזרת התופעה של תזכורות עד 2049.

### חלות לפי תדירות

<div dir="rtl" align="right">

| תדירות | חל בחודש |
|---|---|
| `monthly` | תמיד |
| `bimonthly` | כש-`(חודש - anchor_month)` זוגי - הלוגיקה הקיימת |
| `annual` | רק ב-`anchor_month`. מועד התזכורת = `anchor_day` באותו חודש |

### dedup

הכלל הקיים נשמר ומורחב לכל חודש בחלון: תזכורת וירטואלית לא נוצרת אם קיימת משימה אמיתית ב-DB עם `related_entity_type = "property_utility"` ואותו `related_entity_id` באותו חודש. סימון "בוצע" יוצר את המשימה האמיתית וחוסם את הווירטואלית - הדפוס הקיים, ללא שינוי.

## שינויים בקוד

הכל מרוכז ב-[utility-schedule.ts](../../../src/lib/domain/utility-schedule.ts), שהוא כבר מודול טהור עם בדיקות.

<div dir="rtl" align="right">

| פונקציה | שינוי |
|---|---|
| `mapUtilityCategory` | `insurance` ממופה לקטגוריה `"Insurance"` - זהה לקטגוריה של התזכורות הישנות, כך שהמיגרציה עקבית |
| `utilityTypeLabel` | `insurance` מחזיר `"ביטוח"` |
| `utilityAppliesThisPeriod` | טיפול ב-`annual` - חל רק ב-`anchor_month` |
| `effectiveResponsibility` | **חדש** - פונקציה טהורה לפי הכללים למעלה |

מידע האכלוס נכנס כטיפוס קלט חדש, בדפוס של שאר הפונקציות הטהורות במודול - הקורא מספק אותו, הפונקציה לא שולפת:

```ts
  property_id: string;

  vacant_since?: string | null;
  /** תחילת החוזה הבא אם כבר נחתם - חוסם את האופק */
  next_lease_start?: string | null;

```

[tasks/page.tsx](../../../src/app/dashboard/tasks/page.tsx) מרכיב את `PropertyOccupancy[]` מהחוזים שכבר נטענים בו, בדיוק כפי שהוא מרכיב היום את `utilitiesWithTitle`.

## ממשק משתמש

**הגדרת חשבון** (עמוד הנכס) - הסוג "ביטוח" נוסף לבורר. בבחירתו התדירות ננעלת על "שנתי", בורר האחריות מוסתר (תמיד הבעלים), ונחשף שדה תאריך חידוש שממלא `anchor_month` ו-`anchor_day`.

**מסך תזכורות** - תזכורות החודש הנוכחי נכנסות ל"רלוונטיות" כמו היום. תזכורות החודשים הבאים של נכס ריק נכנסות ל"עתידיות", שכבר מוגבל לאופק של שנה מעבודה קודמת. לא נדרש מקטע חדש.

**סימון ויזואלי** - תזכורת של נכס ריק מקבלת תגית `נכס ריק` כדי להבהיר למה החשבון חל עליך ולא על השוכר.

## מיגרציה של 72 השורות הישנות

לאחר המימוש, ולפני המחיקה, בסדר הזה:

1. הגדרת ביטוח כחשבון `annual` בכל נכס רלוונטי, עם תאריך החידוש האמיתי.
2. אימות שתזכורת החידוש הבאה מופיעה נכון במסך.
3. רק אז - מחיקת 72 השורות הישנות (`related_entity_type = "lease"` בקטגוריות שירות וביטוח, שמועדן מעבר לאופק).

המחיקה עצמה טעונה אישור מפורש של אמיר בעת הביצוע - היא נגיעה בדאטה היסטורית.

## בדיקות

<div dir="rtl" align="right">

| מה נבדק |
|---|
| `effectiveResponsibility` - ביטוח תמיד `owner_pays` · נכס ריק הופך `tenant_pays` ל-`owner_pays` · נכס מאוכלס משמר את ההגדרה |
| חשבון `tenant_pays` **מייצר** תזכורת בנכס ריק ו**לא מייצר** בנכס מאוכלס |
| `annual` חל רק ב-`anchor_month`, והמועד הוא `anchor_day` |
| האופק נעצר ב-31.12 · נעצר יום לפני תחילת החוזה הבא כשזה מוקדם יותר |
| נכס מאוכלס מייצר לחודש הנוכחי בלבד |
| dedup - משימה אמיתית קיימת חוסמת את הווירטואלית באותו חודש, ולא בחודש אחר |
| הצטברות - הרצה בתאריך 1.1 מייצרת עד סוף השנה החדשה ולא מעבר |

</div>

**בדיקה ידנית ב-Playwright** לפי סקיל `verify`: הגדרת ביטוח שנתי בנכס ואימות הופעת תזכורת החידוש; סיום חוזה ואימות שתזכורות החשבונות עוברות לבעלים עד סוף השנה, כולל אלה שהוגדרו `tenant_pays`.

## מה מחוץ לגבולות

- **סכומים ותחזית עלות כספית** לנכס ריק - נדחה במפורש לשלב זה. אם יתווסף בעתיד, המקור המועדף הוא ממוצע ההוצאות ההיסטוריות לאותו נכס וקטגוריה, עם אפשרות דריסה ידנית.
- **ראייה קדימה לנכס מאוכלס** - נשאר חודש נוכחי בלבד.
- **תזכורות אוטומטיות סביב עזיבה** (החזרת פיקדון, קריאת מונים, מסירת מפתחות) - שייך לסשן "עזיבה ופינוי".
