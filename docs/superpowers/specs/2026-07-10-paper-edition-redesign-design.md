# יומן הספר - "מהדורת נייר": רדיזיין בהיר + היררכיית דשבורד

תאריך: 2026-07-10 · סטטוס: מאושר עקרונית ע"י אמיר (mockup v2), ממתין לאישור spec

## רקע והחלטה

סבב מחקר רב-סוכני (4 זוויות: אפליקציות ניהול נכסים, אפליקציות פיננסים, ראיות כהה/בהיר, מגמות 2025-2026) הכריע:

- **מעבר לבהיר-בלבד.** כל 7 אפליקציות ניהול הנכסים שנבדקו בהירות כברירת מחדל; מחקרי קריאוּת (positive polarity) מעדיפים בהיר לטקסט/מספרים/טבלאות; קהל 35-65 (presbyopia מגיל 40+) נהנה מיותר אור; שימוש קצר בשעות היום מבטל את יתרונות הכהה; ערכה אחת = חצי עלות תחזוקה. אין ערכה כהה - לא נבנה theme switcher.
- **הנחת שימוש מכוננת: ביקור אחת לכמה ימים**, 1-3 דקות, "נכנס - בודק - יוצא". הדשבורד עונה קודם על "מה קרה מאז?" ו"מה דורש טיפול?".
- **בחירות אמיר על גבי mockup חי** (artifact, v2): ערכת **קלף** · פונט **Heebo** לכל דבר · **כותרות וספרות באותו פונט כמו הגוף** (הסריף Frank Ruhl Libre יוצא).

## 2. טיפוגרפיה - Heebo אחיד

- **פונט יחיד: Heebo** (400 / 500 / 700) - גוף, כותרות, ספרות. Rubik ו-Frank Ruhl Libre מוסרים מ-`layout.tsx` (next/font) ומכל ה-CSS.
- `--font-display` לא נמחק אלא מוצב על Heebo (המון קוד מפנה אליו); `h1, h2` במשקל 700. מחלקת `.font-display` נשארת כ-alias.
- **מספר-גיבור**: Heebo 700 בגודל `text-5xl` (ספרות "כמו הגוף" - הבחירה של אמיר, משקל 700 ולא 900).
- `font-variant-numeric: tabular-nums` מורחב מ-`td, th, .font-semibold, .font-bold` לכל רכיב שמציג סכום (utility `.tnum` + הוספה לרכיבי הסכומים).
- **בידוד כיוון למספרים**: מחלקת עזר `.num-ltr { direction: ltr; unicode-bidi: isolate; }` על כל תאריך/סכום/טווח-תאריכים בתוך טקסט עברי.

## 3. דשבורד - היררכיה חדשה (מסך הבקרה)

סדר חדש מלמעלה למטה, בנוי לביקור אחת לכמה ימים:

1. **"מאז הביקור האחרון"** - כרטיס בגוון accent-dim. חותמת הביקור נשמרת ב-`localStorage` (per-device, פשוט וללא DB). מציג: תקבולים שנכנסו מאז (מספר + סכום), תזכורות שסומנו, חובות חדשים ("אין" בירוק כשאין). לא מוצג בביקור ראשון או כשאין כלום לדווח.
2. **"דורש טיפול"** - כרטיס עם פס צד כתום. מקורות: תקבולים באיחור, שקים להפקדה בטווח הקרוב, חוזים שמסתיימים (עד 90 יום), תזכורות להיום. נעלם לגמרי כשאין כלום (המסך "נושם" כשהכל תקין).
3. **מספר-גיבור** - "תזרים החודש, אחרי מס" במרכז, Heebo 700 גדול, ומתחתיו שורת מגמה: "עלייה/ירידה של X% מהחודש שעבר" (ירוק/אדום; משולש ▲/▼ קטן, בלי חצים).
4. **KPI קטנים** - נכסים / חוזים פעילים / ממתינים, קטנים מובהקות מהגיבור.
5. **כרטיסי הכנסה/הוצאות** - גרדיאנטים סמנטיים, טקסט לבן (קיים).
6. **תנועות אחרונות מקובצות** - "השבוע" / "שבוע שעבר" / חודש קודם לפי שם - במקום תאריך מלא בכל שורה (רזולוציה שמתאימה לביקור לא-יומי).

כפתורי הפעולה המהירה (ייבוא חוזה, נכס חדש, דוחות, דוח מס) נשארים, מתחת לברכת השלום.

## 4. היקף טכני

- **`globals.css`**: החלפת ערכי הטוקנים + עדכון שכבת ה-overrides (אותה ארכיטקטורה: mapping של מחלקות Tailwind בהירות אל הטוקנים). חלק מה-overrides מתבטלים (המחלקות המקוריות כבר נכונות על רקע בהיר) - מוחקים override, לא markup. מיפויי pink הישנים נשארים (רשת ביטחון). בלוק ה-print לא מושפע.
- **`layout.tsx`**: החלפת imports של next/font ל-Heebo בלבד; `--font-rubik` מקבל alias או מוחלף בהדרגה (`--font-body`).
- **`manifest.ts`**: `theme_color: "#f3edde"`, `background_color: "#f3edde"` (סוגר את ממצא פס-הסטטוס הכחול מבדיקת המכשיר). הצעה כלולה: `name: "יומן הספר - ניהול נכסים"`, `short_name: "יומן הספר"` (כיום "מנהל נכסים להשכרה" - שם שקדם למיתוג).
- **דף נחיתה + מסכי auth**: מעבר לאותה ערכת קלף (כיום כהים עם רקע מרושט - הרישוט יותאם לקלף).
- **דשבורד**: מימוש ההיררכיה החדשה בסעיף 3 (כולל לוגיקת "מאז הביקור" ו"דורש טיפול" בצד לקוח מנתונים שכבר נטענים ב-TanStack Query - בלי endpoints חדשים אם אפשר).
- **בדיקות**: vitest קיים לא מושפע (לוגיקה פיננסית); בדיקות חדשות ללוגיקת "דורש טיפול" ו"מאז הביקור" (פונקציות טהורות ב-`src/lib/domain/`).

4. tsc / lint / vitest / build ירוקים; פריסה אוטומטית ירוקה.
5. אין רגרסיה בדוח המס המודפס (print נשאר כשהיה).
