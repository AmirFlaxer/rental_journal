# אפיון: מודול בטחונות (Lease Securities)

> נוצר 2026-07-24 בעקבות brainstorming עם אמיר.

## הבעיה

בתחילת חוזה, המשכיר מקבל מהשוכר **בטחונות** להבטחת ההתקשרות:
- **שק ביטחון** / **שטר ביטחון** - נייר שמוחזק כערבות, לא נפדה, מוחזר בסוף.
- **שקים ייעודיים** לחברות שירות (חשמל, מים, גז, ארנונה) - מוחזקים כערבות.
- **פיקדון כספי** - תשלום מראש שהתקבל בפועל, אך הוא **התחייבות** (לא הכנסה) ומוחזר לשוכר בסוף.

היום אין באפליקציה מקום לתעד ולעקוב אחרי הבטחונות האלה. קיים רק שדה `deposit_amount` בודד על החוזה (מספר אינפורמטיבי) ו-`payment_type=Deposit/Return` בתקבולים.

## המטרה

מעקב סטטוס ידני אחרי כל הבטחונות המוחזקים תחת חוזה, במקום אחד. **לא** תזכורות אוטומטיות, **לא** תנועת כסף אוטומטית, **לא** אינטגרציה לדוחות. רק תיעוד ומעקב.

## מודל הנתונים

טבלה חדשה `lease_securities`:

<div dir="rtl" align="right">

| שדה | טיפוס | הערה |
|---|---|---|
| `id` | uuid PK | |
| `user_id` | uuid | בעלות, ל-RLS |
| `lease_id` | uuid FK | הבטחון שייך לחוזה |
| `property_id` | uuid FK | לשליפה מהירה בעמוד הנכס |
| `kind` | text | `security_check` · `promissory_note` · `utility_check` · `cash_deposit` · `other` |
| `utility_type` | text nullable | `electricity`/`water`/`gas`/`municipal_tax` - רק כש-`kind=utility_check` |
| `amount` | numeric nullable | שק/שטר פתוח יכול להיות בלי סכום; לפיקדון כספי - מספר חובה בפועל |
| `bank` | text nullable | פרטי שק |
| `branch` | text nullable | פרטי שק |
| `account` | text nullable | פרטי שק |
| `check_number` | text nullable | מספר שק |
| `status` | text | `held` (מוחזק, ברירת מחדל) · `returned` (הוחזר לשוכר) · `cashed` (נפדה/הופקד) |
| `received_date` | date nullable | מתי התקבל |
| `resolved_date` | date nullable | מתי הוחזר/נפדה |
| `notes` | text nullable | חופשי |
| `created_at` | timestamptz | `default now()` |

</div>

- CHECK constraints על `kind` ו-`status` (בדפוס `property_utilities`).
- RLS: קריאה/כתיבה למשתמש הבעלים בלבד (כמו כל הטבלאות).
- מיגרציה: `supabase/migrations/20260724_lease_securities.sql`, מורצת ידנית ב-Supabase Dashboard (בדפוס הפרויקט).
- אחרי המיגרציה: `npm run gen:types` ואז `npx tsc --noEmit`.

## API

`/api/lease-securities` בדיוק בדפוס `/api/property-utilities` הקיים:
- `GET ?property_id=` / `GET ?lease_id=` - שליפת בטחונות.
- `POST` - יצירה.
- `/api/lease-securities/[id]` - `PUT` (עדכון, כולל שינוי סטטוס) / `DELETE`.
- ולידציה: `leaseSecuritySchema` חדש ב-`src/lib/validations.ts` (בדפוס `propertyUtilitySchema`).

## UI - כרטיס בעמוד הנכס

כרטיס "בטחונות" ב-`/dashboard/properties/[id]`, ליד ווידג'ט תזכורות-השקים הקיים.

**היקף התצוגה:** הבטחונות של החוזה הנוכחי של הנכס (החוזה הפעיל לפי `effectiveLeaseStatus`; אם אין פעיל - האחרון לפי `start_date`). בנוסף, בטחונות בסטטוס `held` מחוזים קודמים של אותו נכס מוצגים בהערה קטנה "מבטחונות קודמים שטרם הוחזרו", כדי שפריט שלא הוחזר לא ייעלם כשמתחיל חוזה חדש.

**שורות סיכום** בראש הכרטיס:
- "פיקדונות כספיים מוחזקים: ₪X" - סכום `amount` של פריטים `kind=cash_deposit AND status=held`.
- "N שקים/שטרות מוחזקים" - ספירת פריטי-נייר בסטטוס `held`.

**רשימת פריטים:** כל פריט מציג אייקון-סוג, תווית, סכום (אם יש), פרטי-שק מקוצרים, ותג-סטטוס. פעולות: הוספה (חלונית קטנה), עריכה, שינוי סטטוס, מחיקה.

**עיצוב:** נשמרת הסמנטיקה הקיימת (ירוק=הכנסה, אדום=הוצאה, כתום=מס) - בטחונות הם **ניטרליים**, לא נכנסים לסכמת ההכנסה/הוצאה. תגי-סטטוס בגוונים ניטרליים (מוחזק=ברירת מחדל, הוחזר=מסומן-בוצע, נפדה=ענבר). אייקונים דרך `Icon`/`@phosphor-icons/react` הקיים (למשל `shield` לשק/שטר ביטחון, אייקון-שירות ל-utility_check, אייקון-כסף ל-cash_deposit) - להוסיף מיפוי ב-`src/lib/icons.ts`.

## לוגיקה טהורה + בדיקות

מודול קטן `src/lib/domain/securities-summary.ts` (פונקציות טהורות):
- `heldCashDepositTotal(items)` - סכום פיקדונות כספיים מוחזקים.
- `heldPaperCount(items)` - ספירת שקים/שטרות מוחזקים.

בדיקות-יחידה ב-`securities-summary.test.ts` (בדפוס שאר `src/lib/domain`).

## מה נשאר ללא שינוי (תאימות לאחור)

- `deposit_amount` על החוזה - נשאר כפי שהוא (אינפורמטיבי, מיובא מ-AI).
- `payment_type=Deposit/Return` בתקבולים - נשאר זמין למי שרוצה רישום תזרים; לא נדרש. מודול הבטחונות הוא המקום המומלץ למעקב.

## מחוץ להיקף (YAGNI)

- אין תזכורות אוטומטיות להחזרה.
- אין סנכרון כסף אוטומטי (שינוי סטטוס לא יוצר תקבול/הוצאה).
- אין אינטגרציה לדוח ההכנסות/הוצאות/מס.
- אין כפתור המרה מ-`deposit_amount` הקיים.
- אין ייבוא-AI של בטחונות מהחוזה (אפשר בעתיד).
