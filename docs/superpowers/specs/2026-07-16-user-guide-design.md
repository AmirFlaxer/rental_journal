# חוברת הסברים למשתמש - Design Spec

> תאריך: 2026-07-16 · פריט ישן מ-SPEC.md (שורטט לראשונה 2026-06-29, נדחה עד שהרדיזיין+מעבר-האייקונים יסתיימו כדי שלא יתיישן)

## 1. רקע ומניע

האפליקציה מכילה כיום פיצ'רים רבים (נכסים, חוזים עם הצמדה/אופציה, תקבולים עם תשלום-חלקי/שיקים, מס אוטומטי, חובות, דוחות, תזכורות) בלי שום הדרכה מובנית. משתמש חדש (או אמיר עצמו אחרי הפסקה) צריך לגלות הכל בניסוי-וטעייה. המטרה: מדריך-שימוש מלא, בעברית פשוטה, נגיש מכל מסך.

## 2. היקף

**בפנים**: מסך `/dashboard/help` עם 9 פרקים - פרק-פתיחה (תחילת-עבודה, 1-2 עמודים) + 8 פרקים לפי קטגוריה (נכסים, חוזים, תקבולים, הוצאות, חובות, דוחות, תזכורות, הגדרות). כפתור-עזרה גלובלי בסרגל-הצד + קפיצה-חכמה לפרק הרלוונטי לפי המסך הנוכחי.

**בחוץ**: אחסון-חיצוני (Notion/GitBook) - נדחה, נבחר עמוד-פנימי. PDF להדפסה - לא התבקש, לא בהיקף. תרגום לאנגלית - לא רלוונטי (אפליקציה בעברית בלבד).

## 3. ארכיטקטורה

- **`src/app/dashboard/help/page.tsx`** - עמוד-TSX רגיל (לא MDX - אין צורך בכלי-בנייה נוסף לתוכן סטטי). כל פרק הוא `<section id="...">` בתוך אותו קובץ, בדיוק כמו הדפוס הקיים ב-`about/page.tsx` (סקציות עם `<h2>` + `tick-accent`, כרטיסי-תוכן לבנים).
- **תפריט-תוכן-עניינים** בראש העמוד - קישורי-עוגן (`#intro`, `#properties` וכו') לכל 9 הפרקים, כדי לנווט בלי גלילה.
- **כפתור-עזרה בסרגל**: אייקון חדש ליד "הגדרות"/"התנתקות" בתחתית-הסרגל (`src/app/dashboard/layout.tsx:90-101`, אותה שורת-אייקונים). דורש הוספת שם-לוגי `guide` (`BookOpenIcon`) ל-`src/lib/icons.ts`.
- **קפיצה-חכמה**: הקישור מחושב לפי `usePathname()` - מיפוי מסך-נוכחי→עוגן-פרק:

  | מסך (prefix) | עוגן |
  |---|---|
  | `/dashboard/properties` | `#properties` |
  | `/dashboard/leases` | `#leases` |
  | `/dashboard/payments` | `#payments` |
  | `/dashboard/expenses` | `#expenses` |
  | `/dashboard/debts` | `#debts` |
  | `/dashboard/reports` | `#reports` |
  | `/dashboard/tasks` | `#tasks` |
  | `/dashboard/settings` | `#settings` |
  | כל השאר (דשבורד/אודות/תחזוקה) | `#intro` (ראש החוברת) |

  ממומש כפונקציה טהורה `chapterAnchorFor(pathname: string): string` - נבדקת ביחידה (vitest, כמו שאר מודולי `src/lib/domain`).

## 4. תוכן - 9 הפרקים

נכתבים במלואם בבת-אחת (לא לפי-דרישה), על סמך סקירה בפועל של המסכים הקיימים (לא המצאה) - טון עברית פשוטה וישירה כמו שאר האפליקציה. מבנה כל פרק: כותרת + 2-4 תת-נושאים + הסבר קצר לכל אחד (לא מדריך-צעד-אחר-צעד ארוך - סיכום שימושי).

0. **פתיחה** - הוספת נכס ראשון, הוספת דייר+חוזה, רישום תקבול ראשון, סיכום זרימת-העבודה החודשית.
1. **נכסים** - הוספה/עריכה, מסמכים, ניהול-נכס (חשבונות-שירות).
2. **חוזים** - ייבוא-AI, עריכה, הצמדה (מדד/דולר), אופציה, סיום-מוקדם, שוכר-שני.
3. **תקבולים** - רישום, תשלום-חלקי, שיקים ותזכורות-הפקדה.
4. **הוצאות** - קטגוריות, מס-אוטומטי 10%.
5. **חובות** - איך לקרוא את דוח-החובות.
6. **דוחות** - דוח-שנתי, דוח-מס, השוואת-מסלולי-הצמדה.
7. **תזכורות** - יצירה, עדיפות, סימון-בוצע, תזכורות-וירטואליות (שק/חוזה).
8. **הגדרות** - ספק-AI, מס-אוטומטי, Web Push, תחזוקה.

## 5. בדיקה

tsc/lint/vitest (כולל טסט-יחידה ל-`chapterAnchorFor`) /build - שערים סטנדרטיים. בדיקה חזותית Playwright: RTL תקין, קפיצת-עוגן עובדת בפועל (לבדוק מ-2-3 מסכים שונים), הטקסט הארוך לא שובר פריסה.

## 6. קריטריוני הצלחה

1. כל 9 הפרקים קיימים ומדויקים לזרימה-האמיתית של האפליקציה.
2. כפתור-עזרה מופיע בכל מסך (הוא בסרגל, לא תלוי-מסך) וקופץ לעוגן הנכון.
3. tsc/lint/vitest/build ירוקים; פריסה אוטומטית ירוקה.
4. בדיקה חזותית מאשרת RTL תקין ופריסה לא-שבורה.
